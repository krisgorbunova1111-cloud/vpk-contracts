## 1. Что это за проект

Одностраничное веб-приложение (единый файл `index.html`) — система управления договорами для компании ВПК. Работает полностью в браузере, без сервера. Данные синхронизируются через Supabase (ключи уже зашиты в коде).

**Стек:** Vanilla JS + HTML + CSS, шрифты Manrope + JetBrains Mono (Google Fonts), никаких фреймворков.

**Хранение данных:**
- `localStorage` — локальный кэш
- Supabase REST API — облачная синхронизация (polling каждые 30 сек)
- Ключи Supabase: `https://urfnpjumxkewyizaxgns.supabase.co`, anon key зашит в функции `loadFromFirebase()`

## 3. Структура объекта договора

```js
{
  id: "1",                          // строка, уникальный ID
  number: "ВПК-Д66-26",            // номер договора
  date: "2026-03-23",              // дата (YYYY-MM-DD)
  contractor: "Иванов И.И.",       // название подрядчика
  inn: "611186223597",             // ИНН
  phone: "8-961-412-29-15",        // телефон
  email: "example@mail.ru",        // email
  object: "Торез",                 // объект (субъект/объект строительства)
  amount: "63600",                 // сумма договора (строка)
  status: "У подрядчика",          // статус договора (см. список ниже)
  responsible: "Мария Костылева",  // ответственный
  days: "21",                      // дней в работе
  comment: "",                     // комментарий
  sign_status: "Подписан",         // статус подписания (см. список ниже)
  payments: [                      // разбивка платежей (опционально)
    {
      key: "advance",              // "advance" | "intermediate" | "final"
      label: "1. Аванс",
      enabled: true,
      amount: "530000",
      week: "10 неделя",
      status: "Оплачен"           // "Оплачен" | "Оплачен частично" | "Ожидается"
    }
  ]
}
```

**Статусы договора (`status`):**
- `Сбор данных`
- `У юриста`
- `У подрядчика`
- `Ожидание счета` → автоматически попадает в раздел «Платежи»
- `Закрыт`
- `Активный`

**Статусы подписания (`sign_status`):**
- `Подписан` — норма
- `На согласовании в Тех депе`
- `На согласовании у заказчика`
- `На согласовании у подрядчика`
- `Договор аннулирован, из-за смены ИП`
- `Расторжение`
- `Не подписан`

Если `sign_status` ≠ `Подписан` — договор попадает в блок **«Особые договоры»** на вкладке Договоры.

## 7. Ключевые функции

### Навигация
```js
showPage(page)  // 'dashboard'|'contracts'|'contractors'|'analytics'|'payments'
```

### Договоры
```js
renderContracts()           // таблица договоров с фильтрами и пагинацией
renderSpecialContracts()    // блок особых договоров (не подписанные)
openContractDetail(id)      // модалка просмотра договора
openContractEdit(id)        // модалка редактирования/создания договора
saveContract(id)            // сохранить договор (id='' для нового)
deleteContract(id)          // удалить договор
openNewContractModal()      // открыть форму нового договора
getFilteredContracts()      // возвращает отфильтрованный+отсортированный массив
```

### Платежи из договоров (синхронизация)
```js
syncPaymentsFromContracts() // договоры со статусом "Ожидание счета" → RAW_PAYMENTS
applyPayStatusToPayments()  // применить сохранённые статусы платежей
rebuildByObjData()          // пересчитать BY_OBJ_DATA
```

### Хранение
```js
saveToStorage()      // сохранить в localStorage + запустить sync в Supabase
loadFromStorage()    // загрузить из localStorage
saveToFirebase()     // сохранить в Supabase
loadFromFirebase()   // загрузить из Supabase (с polling)
```

### Вспомогательные
```js
fmt(n)              // форматировать число в рубли: "1 325 000 ₽"
escape(s)           // HTML-escape строки
statusBadge(s)      // HTML-бейдж статуса
daysBadge(d)        // цветной HTML для количества дней
tonum(v)            // строку/число → float
```

## 8. Что было сделано в ходе работы (история изменений)

### Изменение 1 — Редактирование сумм в существующих договорах
- Поле `#f-amount` в форме редактирования было и осталось редактируемым
- **Исправлено:** убраны 2 дублирующихся поля `#f-sign-status` в форме (было 3 штуки с разными `onchange`, осталось одно — `onchange="checkSignStatus()"`)

### Изменение 2 — Платежи из RAW_PAYMENTS в карточке договора
В функции `openContractDetail(id)` после основного контента добавлен блок:
```js
const relatedPayments = RAW_PAYMENTS.filter(p => p.cn === c.number || p.cn === c.number.trim());
```
Если найдены — рисует секцию **«📊 Платежи из таблицы»** с итогами и детализацией по каждому платежу.

### Изменение 3 — Список объектов (субъектов) в форме договора
Поле `<input id="f-object">` заменено на:
```html
<select id="f-object" onchange="onObjectSelectChange()">
  <option value="">— Выберите объект —</option>
  <!-- 28 объектов из списка выше -->
  <option value="__new__">➕ Добавить новый объект...</option>
</select>
<div id="f-object-custom-wrap" style="display:none">
  <input id="f-object-custom" placeholder="Введите название нового объекта">
</div>
```
Функция `onObjectSelectChange()` показывает/скрывает кастомный input.
При сохранении `saveContract()` читает:
```js
object: f-object.value === '__new__' ? f-object-custom.value : f-object.value
```

### Изменение 4 — Загрузка 133 договоров из Excel
Из файла `Новая_таблица__1_.xlsx` (лист «Договора») извлечены все уникальные договоры и добавлены в `CONTRACTS_INIT`. Каждый договор содержит разбивку платежей (`payments[]`) с ключами `advance`/`intermediate`/`final`.

**Порядок в массиве `CONTRACTS_INIT`:**
1. Первые 8 — исходные договоры ВПК-Д66-26...ВПК-Д73-26 (id: 1–8)
2. Далее 133 — из Excel (id: 9–141)
