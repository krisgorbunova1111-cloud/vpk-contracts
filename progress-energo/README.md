# «Конвейер ИД» — ООО ВПК «Прогресс Энерго»

Прототип системы «от выезда на объект до готового тома ИД, РД и сметы».
Работает на демо-данных (7 выдуманных объектов), всё можно нажимать и ломать —
кнопка **«↺ Демо»** вверху возвращает исходное состояние.

## Как запустить (проще всего)

1. Дважды щёлкнуть **`start.bat`** в этой папке.
2. Браузер откроется сам на http://localhost:8010
   Если не открылся — откройте адрес вручную. Окно с чёрным экраном не закрывать, пока работаете.

Нужно один раз: установленный Python (уже есть на этом компьютере). При первом запуске
`start.bat` сам доставит недостающие библиотеки.

## Что внутри (5 модулей ТЗ)

| Модуль | Где в меню | Что умеет в прототипе |
|---|---|---|
| ★ Конвейер | «Конвейер объектов» | Все объекты по 7 этапам, приоритет цветом, перевод «Дальше →» |
| 1. Планирование | «Планирование» | Недельный календарь выездов, авто-план, расчёт трудозатрат с пояснением, чек-лист допусков + заявка на допуск в Word, приоритет, новый объект |
| 2. Планшет | «Планшет (выезд)» | Крупные кнопки, тёмная тема, QR/список, чек-лист (конструкции, ЭОМ/ВК/ОВ/ТС, узлы, материалы, работы), «Старт сканирования», загрузка облака точек, голосовой ввод и разбор текста ИИ-помощником, авто-заявка в лабораторию |
| 3. Облака точек | «Облака точек и ИИ» | Хранилище .las/.e57/.ptx, индексация → векторизация (имитация) → обмерный план, отметки на плане с координатами |
| 4. Генератор ИД/РД | «Генератор ИД и РД» | Проверка готовности данных, сборка тома ИД (Word) в порядке РД-11-02-2006, заготовки разделов АР/КР/ОВ/ВК/ЭОМ/ТС, автоподстановка сертификатов, печать/сшивка/подпись |
| 5. Сметы | «Сметы и выгрузки» | Авто-смета ПИР (площадь × нормы × коэффициенты, НДС 22%), XML для Гранд-Сметы/ЦСМ, пакет для «Аксон» |
| + Лаборатория, Справочники | | Заявки и их статусы; материалы с сертификатами, типовые узлы |

Роль (диспетчер, сканерщик, камеральщик, проектировщик, архивариус) выбирается вверху —
меню перестраивается под роль.

## Что пока «заглушка» (честно)

- **Векторизация облака** — план строится по шаблону, а не из реальных точек. Нужен выбор сервиса (PointCab, Autodesk ReCap, своя ML-модель).
- **ИИ-помощник** — разбирает текст по ключевым словам; анализ фото возвращает пример. Подключение настоящей нейросети — следующий этап.
- **QR-код** — сканирование имитируется (можно ввести код объекта вручную).
- **Расценки сметы** — внутренние нормы-заглушки в файле `backend/app/calc.py`.
- **XML Гранд-Сметы / Аксон** — упрощённый формат, точную схему нужно согласовать.
- **Нет входа по паролю** и разграничения прав — роль просто выбирается.
- **Хранилище** — один файл `backend/data/db.json`. Для боевой версии — PostgreSQL + файловое хранилище для облаков (они весят гигабайты).

## Для разработчика

```
backend/   Python, FastAPI — API на порту 8010 (документация: /docs)
  app/main.py     все адреса API
  app/calc.py     трудозатраты, смета, разбор текста, план
  app/docgen.py   генерация Word (python-docx)
  app/seed.py     демо-данные
frontend/  React + Vite
  src/pages/      по файлу на экран
  src/styles.css  фирменный стиль (цвета в :root)
```

Режим разработки: `python -m uvicorn app.main:app --port 8010 --reload` в `backend/`
и `npm run dev` в `frontend/` (http://localhost:5180, запросы /api проксируются на 8010).
После правок интерфейса: `npm run build` — сервер на 8010 раздаёт папку `frontend/dist`.
